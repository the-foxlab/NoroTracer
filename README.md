# Norovirus phylogenetic analysis pipeline

## Overview

This repository is under active development and will evenutally provide a Nextflow pipeline for turning nationwide norovirus amplicon sequencing data into actionable pathogen surveillance data. Developed for integration into the [**GenSurv platform**](https://www.netzwerk-universitaetsmedizin.de/forschung/num-sar/module/gensurv), it serves as a use case for showcasing the capabilities of the newly developed platform for pathogen surveillance. Specific to noroviruses, this pipeline aims to detect potential transmission chains through phylogenetic and machine-learning approaches.

 The pipeline currently operates on consensus genomes generated by [`amplicon-nf`](https://github.com/artic-network/amplicon-nf), with direct integration of the upstream consensus-generation workflow planned. These genomes are complemented with automatically identified closely related reference genomes from the [Calicivirus Typing Tool](https://calicivirustypingtool.cdc.gov). The resulting alignments provide the input for downstream phylogenetic reconstruction and clustering approaches aimed at identifying potential chains of infection.

The pipeline is under active development, with additional analysis steps and tighter integration with [`amplicon-nf`](https://github.com/artic-network/amplicon-nf) planned.


## Current workflow status

The following steps are currently implemented

1. downloading Norovirus Genotype II data from the [Calicivirus Typing Tool](https://calicivirustypingtool.cdc.gov)
2. computing pairwise consensus/reference similarities using edlib to find the closest reference genome
3. selecting the closest GenBank records per consensus
4. extracting ORF1 and ORF2 from the consesnus using the closest GenBank record and [gb2seq](https://github.com/VirologyCharite/gb2seq)
5. Computing a MSA with Mafft and basic ML tree with iqtree3 for each ORF
6. Testing setup using github actions

## Requirements

- Nextflow
- Python 3
- Docker (for the gb2seq runtime image and containerized execution)
- optionally: conda, if you prefer to run the tests outside Docker

## Running the current workflow

```bash
nextflow run main.nf -params-file params.yaml -with-docker
```

The current workflow is designed around the runtime parameters in `params.yaml` and uses the local project scripts in `bin/`.

## gb2seq runtime container

The Python steps that depend on [gb2seq](https://github.com/VirologyCharite/gb2seq) are executed in a custom runtime container built from the upstream [gb2seq](https://github.com/VirologyCharite/gb2seq) repository. The image is built from a fixed revision and tagged as `gb2seq:runtime`:

```bash
docker build --target runtime -t gb2seq:runtime -f - https://github.com/VirologyCharite/gb2seq.git\#9db97d50185970403bb3265c19ade641f0e9c260 < Dockerfile
```

Two container images are available at the [github container registry](ghcr.io/udogi/gb2seq-env:0.1.0-dev). A runtime container used for pipeline execution and a development container used for running the tests and active development:

```bash
docker pull ghcr.io/udogi/gb2seq-env:0.1.0-dev
docker pull ghcr.io/udogi/gb2seq-env:0.1.0-runtime
```


## Tests

The project includes a pytest suite under `tests/` that validates the Python scripts and resource-backed fixture data in `tests/resources/`.

### Automated testing in GitHub Actions

Tests are run automatically on every pull request and push to `main` via the GitHub Actions workflow in `.github/workflows/tests.yml`. The workflow:

1. Checks out the repository
2. Pulls the `gb2seq:dev` test container image from GitHub Container Registry
3. Runs all pytest tests inside the container
4. Validates that the `gb2seq:runtime` image can be successfully pulled and basic imports work

The automated tests must pass before code is merged to `main`.

### Running tests locally

You can run the tests locally to validate changes before pushing. There are two approaches:

#### With Docker (recommended, matches CI environment)

Run the tests inside the same container used by GitHub Actions:

```bash
docker run --rm \
  -e PYTHONPATH=/workspace:/workspace/bin \
  -v "$(pwd):/workspace" \
  -w /workspace \
  ghcr.io/udogi/gb2seq-env:0.1.0-dev \
  python -m pytest -q -p no:cacheprovider tests
```

This ensures your local test results match the CI environment exactly.

#### With conda (if gb2seq dependencies are available)

Alternatively, run tests in your local conda environment:

```bash
conda run -n my_env pytest -q tests
```

This requires that `gb2seq` and its dependencies are installed in the `my_env` conda environment.
